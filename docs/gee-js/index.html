Google Earth Engine dengan JavaScript

Workshop 90 menit untuk pemula. Dari belum pernah membuka Code Editor, sampai punya satu skrip utuh yang mendeteksi kehilangan vegetasi dari citra Sentinel-2 dan mengekspornya sebagai GeoTIFF.

90 menit JavaScript Tanpa instalasi Sentinel-2 Gratis untuk riset & pendidikan

Halaman ini berbeda dari tutorial utama repositori ini, yang memakai Python dan paket earthchange. Di sini kita tidak memasang apa pun. Semua dikerjakan di dalam peramban, lewat Code Editor milik Google Earth Engine.

Kenapa JavaScript, padahal repositori ini Python? Karena untuk orang yang baru pertama kali menyentuh penginderaan jauh berbasis awan, Code Editor jauh lebih ramah: tidak ada instalasi, tidak ada environment yang bentrok, tidak ada autentikasi yang gagal di menit ketiga. Anda buka tautan, ketik, tekan Run, dan petanya langsung muncul di bawah. Konsepnya sama persis dengan versi Python — yang berbeda hanya tempat mengetiknya.

Di akhir 90 menit, kita akan lihat bahwa skrip yang kita bangun bersama-sama itulah yang diotomatiskan oleh earthchange menjadi satu baris perintah.

0 · Persiapan — kerjakan sebelum kelas

⚠ Ini bagian yang paling sering merusak jadwal Pendaftaran Earth Engine tidak instan — perlu membuat proyek Google Cloud dan persetujuannya bisa memakan waktu. Kalau peserta baru mendaftar saat kelas dimulai, Sesi 2 bisa molor 20–30 menit dan seluruh rundown berantakan.

Kirim langkah 1–3 di bawah ke peserta minimal sehari sebelumnya, dan minta mereka membalas dengan tangkapan layar Code Editor yang sudah terbuka.
  1. Akun Google. Akun kampus (@students.undip.ac.id dan sejenisnya) biasanya bisa. Kalau ditolak organisasinya, pakai akun pribadi.
  2. Daftar Earth Engine di code.earthengine.google.com. Anda akan diminta memilih atau membuat Cloud Project, lalu memilih jenis penggunaan. Untuk kuliah dan riset, pilih yang non-commercial / academic — gratis.
  3. Pastikan Code Editor terbuka dan Anda melihat peta dunia di bagian bawah layar. Kalau sampai di sini, persiapan selesai.
  4. Peramban. Chrome paling mulus. Code Editor jalan di Firefox dan Safari, tapi beberapa panel kadang berperilaku aneh.
  5. Koneksi. Semua perhitungan terjadi di server Google, jadi yang dikirim bolak-balik hanya gambar peta. Tidak butuh internet kencang, tapi butuh yang stabil.

1 · Kenapa Earth Engine 10 menit

Mulai dengan pertanyaan ke peserta: kalau ingin melihat perubahan tutupan lahan satu kabupaten selama sepuluh tahun, apa yang harus dilakukan?

Jawaban cara lama: cari citra di katalog, unduh satu per satu, tiap scene ratusan MB, koreksi atmosfer, mozaik, potong, baru analisis. Untuk sepuluh tahun satu kabupaten, itu bisa ratusan gigabyte dan berminggu-minggu kerja — sebelum satu pun kesimpulan lahir.

Earth Engine membalik urutannya. Datanya tidak pindah ke Anda; kode Anda yang pindah ke datanya. Seluruh arsip Landsat sejak 1984, Sentinel sejak 2015, MODIS sejak 2000, ditambah ratusan dataset lain, sudah duduk di server Google. Anda menuliskan apa yang ingin dihitung, Google yang mengerjakan, dan yang dikirim balik ke layar Anda cuma gambar petanya.

Yang perlu ditegaskan sejak awal supaya tidak menimbulkan salah paham nanti: gratisnya untuk penggunaan non-komersial — riset, pendidikan, dan sebagian besar kerja lembaga publik. Penggunaan komersial berbayar. Dan "gratis" bukan berarti "tanpa batas": ada kuota memori dan waktu komputasi, yang akan kita temui sendiri di Sesi 6.

Yang akan kita bangun hari ini Satu skrip yang membandingkan tutupan vegetasi di sebuah kawasan tambang nikel di Konawe Utara, Sulawesi Tenggara, antara 2023 dan 2026 — lalu menghitung berapa hektar vegetasi yang hilang, dan mengekspor hasilnya sebagai GeoTIFF.

Skripnya tumbuh sedikit demi sedikit di tiap sesi. Tidak ada langkah yang dibuang.

2 · Tur Code Editor 10 menit

Buka code.earthengine.google.com. Sekilas layarnya padat, tapi sebetulnya hanya ada empat bagian yang perlu dikenali hari ini.

Kiri — Scripts / Docs / Assets Scripts menyimpan skrip Anda. Docs adalah dokumentasi lengkap semua fungsi — ini yang paling sering dilupakan pemula, padahal isinya jawaban dari 90% pertanyaan. Assets untuk data Anda sendiri, misalnya shapefile batas wilayah.
Tengah — Editor kode Tempat mengetik. Tombol Run menjalankan seluruh skrip dari atas ke bawah. Tombol Save menyimpan. Get Link membuat URL yang berisi skrip Anda — cara terbaik membagikan pekerjaan ke rekan atau ke dosen pembimbing.
Kanan — Console / Inspector / Tasks Console menampilkan hasil print(). Inspector membaca nilai piksel saat Anda mengklik peta — alat debug paling berguna di GEE. Tasks tempat ekspor dijalankan.
Bawah — Peta Setiap Map.addLayer() menambah satu lapisan di sini. Panel Layers di pojok kanan atas peta bisa dipakai mengatur transparansi dan mematikan lapisan — sangat membantu saat membandingkan sebelum/sesudah.

Sekarang, baris pertama. Ketik ini di editor tengah, lalu tekan Run:

print('Halo GEE');

Lihat ke panel Console di kanan. Kalau muncul Halo GEE, semuanya siap.

Sekarang coba yang sedikit berbeda — perhatikan hasilnya:

print(ee.Number(2).add(3));

Console menampilkan 5. Tapi ada yang penting terjadi di balik layar: penjumlahan itu tidak dikerjakan oleh peramban Anda. Ia dikirim ke server Google, dihitung di sana, lalu hasilnya dikirim balik. Untuk 2+3 ini terdengar berlebihan — dan memang berlebihan — tapi mekanisme yang sama persis itulah yang nanti memproses ribuan citra tanpa mengunduh satu pun.

Tugas 1 · 2 menit Simpan skrip ini (Save, beri nama workshop-gee), lalu klik Get Link dan tempel tautannya di grup kelas. Kita akan pakai skrip ini terus sampai akhir.

3 · JavaScript secukupnya 15 menit

Kabar baiknya: Anda tidak perlu bisa JavaScript untuk memakai Earth Engine. Yang dibutuhkan cuma sekitar enam hal, dan semuanya muat di satu layar.

// Komentar diawali dua garis miring — server mengabaikannya.

var angka = 5;                       // variabel: selalu diawali 'var'
var teks = 'Konawe Utara';           // teks pakai kutip tunggal
var daftar = [1, 2, 3];              // daftar (list)
var kamus = {min: 0, max: 3000};     // kamus (dictionary) — sangat sering dipakai

function tambah(a, b) {              // fungsi
  return a + b;
}

print(tambah(2, 3));                 // 5

Itu saja. Titik koma di akhir baris sebetulnya opsional, tapi biasakan menulisnya — ia menghindarkan sejumlah kesalahan yang sulit dilacak.

Perhatikan kamus di atas. Bentuk {nama: nilai} itu akan muncul terus, karena hampir semua fungsi Earth Engine menerima pengaturannya dalam bentuk itu.

Bagian terpenting seluruh workshop: klien vs server

Kalau dari 90 menit ini hanya satu hal yang diingat peserta, buat itu bagian ini. Hampir semua kebingungan pemula di GEE berakar di sini.

Ada dua dunia yang hidup berdampingan di dalam satu skrip:

Klien (peramban Anda)Server (Google)
Contohvar a = 5;var b = ee.Number(5);
CiriJavaScript biasaSelalu diawali ee.
Dihitung diLaptop AndaData center Google
Boleh pakai if/for?BolehTidak

Kenapa if tidak boleh dipakai pada objek server? Contoh ini yang paling jelas menunjukkannya:

var b = ee.Number(1);

if (b.gt(3)) {
  print('lebih besar dari 3');       // ini TETAP tercetak!
}

Padahal 1 jelas tidak lebih besar dari 3. Kenapa tetap tercetak?

Karena b.gt(3) tidak mengembalikan true atau false. Ia mengembalikan sebuah objek ee.Number — perintah yang belum dijalankan, yang baru akan dievaluasi di server nanti. Dan di JavaScript, objek apa pun dianggap "benar". Jadi blok if itu selalu jalan, apa pun isinya.

Ini bukan bug. Ini konsekuensi dari kenyataan bahwa peramban Anda belum tahu nilainya — dan tidak akan tahu sampai server menghitungnya.

Hal yang sama berlaku untuk perulangan. Jangan pernah menulis for untuk memproses isi sebuah koleksi citra:

// SALAH — for-loop tidak bisa menyentuh isi ImageCollection
for (var i = 0; i < koleksi.size(); i++) { ... }

// BENAR — .map() menyuruh server melakukannya untuk setiap citra
var hasil = koleksi.map(function(citra) {
  return citra.normalizedDifference(['B8', 'B4']);
});

.map() adalah cara Earth Engine berkata "kerjakan fungsi ini pada setiap elemen, di sisimu, secara paralel". Untuk ribuan citra, bedanya bukan soal gaya penulisan — for memang tidak akan berhasil sama sekali.

⚠ getInfo() — pakai sehemat mungkin getInfo() memaksa hasil dari server pindah ke peramban sekarang juga, dan peramban akan membeku sampai selesai.

print(koleksi.size());  ← benar, print menanganinya secara asinkron
var n = koleksi.size().getInfo();  ← jalan, tapi memblokir; hindari kecuali benar-benar perlu
Tugas 2 · 3 menit Ubah ee.Number(1) di contoh if tadi menjadi ee.Number(10). Jalankan. Apakah hasilnya berubah? Kenapa tidak?

Lalu perbaiki dengan cara Earth Engine — pakai ee.Algorithms.If(), atau yang lebih lazim, hindari percabangan sama sekali dan pakai mask. Kita akan memakai mask di Sesi 5.

4 · Citra pertama 15 menit

Mulai dari yang paling sederhana dan paling pasti ada: model elevasi digital SRTM. Satu citra, satu band, tersedia untuk hampir seluruh daratan bumi.

// Titik pusat kawasan yang akan kita amati:
// Mandiodo, Konawe Utara, Sulawesi Tenggara
var titik = ee.Geometry.Point([122.25, -3.333]);
var area  = titik.buffer(6000);      // radius 6 km, satuannya METER

Map.centerObject(area, 12);          // 12 = tingkat perbesaran

var dem = ee.Image('USGS/SRTMGL1_003');
Map.addLayer(dem, {min: 0, max: 800}, 'Elevasi');

Tekan Run. Peta bergeser ke Sulawesi Tenggara dan muncul lapisan abu-abu: gelap untuk rendah, terang untuk tinggi.

Tiga hal yang perlu diperhatikan dari potongan kode itu:

  • Urutan koordinat adalah [bujur, lintang] — longitude dulu, baru latitude. Ini kebalikan dari kebiasaan menyebut "lintang-bujur", dan menjadi salah satu kesalahan paling sering. Kalau peta Anda melompat ke tengah laut, periksa ini lebih dulu.
  • buffer() memakai satuan meter, bukan derajat.
  • {min:0, max:800} adalah parameter visualisasi — ia hanya mengatur tampilan, tidak mengubah data. Kalau petanya tampak putih semua atau hitam semua, hampir selalu inilah penyebabnya, bukan datanya.

Sekarang beralih ke citra optik. Alih-alih menghafal ID satu citra tertentu, kita ambil citra pertama dari koleksi yang sudah disaring — cara yang lebih aman dan sekaligus memperkenalkan penyaringan:

var satuCitra = ee.ImageCollection('COPERNICUS/S2_SR_HARMONIZED')
  .filterBounds(area)
  .filterDate('2026-01-01', '2026-06-30')
  .sort('CLOUDY_PIXEL_PERCENTAGE')   // paling sedikit awan di urutan pertama
  .first();

print('Citra terpilih:', satuCitra);

// Warna asli: merah, hijau, biru
Map.addLayer(satuCitra, {bands: ['B4', 'B3', 'B2'], min: 0, max: 3000}, 'Warna asli');

// Warna semu: inframerah-dekat sebagai merah — vegetasi jadi merah menyala
Map.addLayer(satuCitra, {bands: ['B8', 'B4', 'B3'], min: 0, max: 3000}, 'Warna semu');

Matikan dan nyalakan kedua lapisan itu bergantian lewat panel Layers. Pada komposit warna semu, vegetasi sehat menyala merah terang — karena daun memantulkan inframerah-dekat jauh lebih kuat daripada cahaya tampak. Sifat inilah yang akan kita manfaatkan di Sesi 6.

Klik tab Inspector, lalu klik satu titik di peta. Panel itu menampilkan nilai setiap band di titik tersebut. Biasakan memakai Inspector — kalau nanti hasil analisis terasa janggal, di sinilah tempat memeriksanya.

Kenapa max: 3000, bukan 255? Sentinel-2 Level-2A menyimpan pantulan permukaan dalam bilangan bulat yang dikalikan 10.000. Jadi nilai 3000 berarti pantulan 0,30 alias 30% — kira-kira batas atas yang wajar untuk vegetasi dan tanah. Kalau citra tampak terlalu gelap, naikkan; terlalu terang, turunkan.

5 · ImageCollection dan komposit median 15 menit

Satu citra jarang cukup di Indonesia — dan peserta biasanya sudah tahu alasannya sebelum kita menyebutkannya. Awan.

Coba tampilkan citra tunggal tadi dan cari bagian yang tertutup awan. Selalu ada. Menunggu satu citra yang benar-benar bersih di atas Sulawesi bisa berarti menunggu berbulan-bulan.

Solusinya bukan mencari citra sempurna, melainkan menggabungkan banyak citra tidak sempurna. Untuk setiap piksel, buang yang tertutup awan, lalu ambil nilai tengah (median) dari sisanya. Awan di citra A ditambal piksel bersih dari citra F, dan seterusnya — otomatis, per piksel.

// Fungsi untuk membuang piksel awan dengan band SCL (klasifikasi scene)
function maskAwan(citra) {
  var scl = citra.select('SCL');
  var bersih = scl.neq(3)      // 3  = bayangan awan
    .and(scl.neq(8))           // 8  = awan probabilitas sedang
    .and(scl.neq(9))           // 9  = awan probabilitas tinggi
    .and(scl.neq(10))          // 10 = cirrus tipis
    .and(scl.neq(11));         // 11 = salju / es
  return citra.updateMask(bersih);
}

// Fungsi pembantu: satu komposit median untuk satu rentang tanggal
function komposit(mulai, selesai) {
  return ee.ImageCollection('COPERNICUS/S2_SR_HARMONIZED')
    .filterBounds(area)
    .filterDate(mulai, selesai)
    .filter(ee.Filter.lte('CLOUDY_PIXEL_PERCENTAGE', 60))
    .map(maskAwan)
    .median();
}

var sebelum  = komposit('2023-01-01', '2023-12-31');
var sesudah  = komposit('2026-01-01', '2026-06-30');

Map.addLayer(sebelum.clip(area), {bands:['B4','B3','B2'], min:0, max:3000}, 'Sebelum 2023');
Map.addLayer(sesudah.clip(area), {bands:['B4','B3','B2'], min:0, max:3000}, 'Sesudah 2026');

Jalankan, lalu bandingkan kedua lapisan dengan menyalakan-mematikannya. Perbedaannya seharusnya sudah terlihat dengan mata telanjang.

Beberapa catatan tentang kode di atas:

  • .filter(ee.Filter.lte('CLOUDY_PIXEL_PERCENTAGE', 60)) membuang scene yang lebih dari 60% berawan. Ini penyaringan per scene; maskAwan bekerja per piksel. Keduanya saling melengkapi.
  • .map(maskAwan) — inilah .map() dari Sesi 3, dipakai sungguhan.
  • .median() meruntuhkan seluruh koleksi menjadi satu citra. Bisa juga .mean(), tapi median lebih tahan terhadap sisa awan yang lolos dari mask.
  • .clip(area) hanya untuk kerapian tampilan.

Ingin tahu berapa citra yang dipakai? Tambahkan ini:

var koleksi2023 = ee.ImageCollection('COPERNICUS/S2_SR_HARMONIZED')
  .filterBounds(area).filterDate('2023-01-01', '2023-12-31');
print('Jumlah citra 2023:', koleksi2023.size());
Konsekuensi yang sering terlewat Komposit median bukan foto satu tanggal — ia nilai tengah periode. Untuk pertanyaan seperti "bagaimana kondisi vegetasi sepanjang 2023", itu justru lebih baik daripada satu tanggal sembarang.

Tapi untuk kejadian sesaat seperti banjir, cara ini keliru: genangan tiga hari akan tenggelam tanpa bekas di median satu tahun. Untuk kasus seperti itu, pakai satu scene, atau pakai radar yang menembus awan.

6 · Deteksi perubahan 15 menit

Sekarang inti workshop. Dan idenya sesungguhnya sederhana: hitung kehijauan pada dua waktu, lalu kurangkan.

Ukuran kehijauan yang paling umum adalah NDVI, yang membandingkan inframerah-dekat (band B8, sangat dipantulkan daun sehat) dengan merah (band B4, banyak diserap klorofil):

var ndviSebelum = sebelum.normalizedDifference(['B8', 'B4']).rename('NDVI');
var ndviSesudah = sesudah.normalizedDifference(['B8', 'B4']).rename('NDVI');

var selisih = ndviSesudah.subtract(ndviSebelum);

Map.addLayer(selisih.clip(area),
  {min: -0.4, max: 0.4, palette: ['red', 'white', 'green']},
  'Selisih NDVI');

normalizedDifference menghitung (B8 − B4) / (B8 + B4), menghasilkan nilai antara −1 dan 1. Vegetasi rapat biasanya di atas 0,6; tanah terbuka sekitar 0,1–0,2; air bernilai negatif.

Pada peta selisih, merah berarti kehijauan berkurang dan hijau berarti bertambah. Kawasan tambang akan terlihat sebagai bercak merah yang tegas.

Peta gradasi itu bagus untuk melihat pola, tapi belum bisa dihitung. Untuk itu kita perlu mengambil keputusan: seberapa besar penurunan yang kita sebut "hilang"?

var AMBANG = -0.15;                  // turun lebih dari 0,15 dianggap kehilangan
var hilang = selisih.lt(AMBANG);

Map.addLayer(hilang.selfMask().clip(area), {palette: ['red']}, 'Kehilangan vegetasi');

.selfMask() menyembunyikan piksel bernilai nol, sehingga yang tergambar hanya area yang benar-benar berubah.

⚠ Angka −0,15 itu pilihan, bukan kebenaran Tidak ada yang menurunkannya dari langit. Ia nilai yang masuk akal, bukan konstanta alam. Ubah menjadi −0,10 dan area merah melebar; −0,25 dan ia menyempit.

Karena itu, saat melaporkan hasil, selalu sebutkan ambang yang dipakai. Pernyataan "wilayah A dua kali wilayah B pada ambang yang sama" jauh lebih kokoh daripada "wilayah A rusak 37,2%".

Terakhir, ubah peta menjadi angka — bagian yang biasanya paling ditunggu:

var luas = hilang.multiply(ee.Image.pixelArea())   // luas tiap piksel, m2
  .divide(10000)                                   // m2 -> hektar
  .reduceRegion({
    reducer:   ee.Reducer.sum(),
    geometry:  area,
    scale:     20,                                 // meter per piksel
    maxPixels: 1e10
  });

print('Luas kehilangan vegetasi (ha):', luas);

reduceRegion meringkas seluruh piksel dalam sebuah wilayah menjadi satu angka. Parameter scale menentukan resolusi perhitungan — dan ia berpengaruh besar pada waktu proses. Untuk latihan, 20 m sudah memadai.

Tugas 3 · 5 menit a. Ganti AMBANG menjadi −0,10 lalu −0,25. Catat luasnya masing-masing. Seberapa besar pengaruh satu keputusan kecil itu terhadap angka yang akan Anda kutip?

b. Ganti koordinat ke wilayah Anda sendiri. Cari di Google Maps, klik kanan, salin koordinatnya — lalu ingat membaliknya menjadi [bujur, lintang].

Untuk pemateri — hasil yang seharusnya muncul, sudah diuji lebih dulu pada AOI seluas 11.175 ha (30 citra pada 2023, 13 citra pada 2026):

AmbangLuas terdeteksiPorsi AOI

Inilah inti Tugas 3, dan sebaiknya ditulis di papan: menggeser satu angka dari −0,10 ke −0,25 mengubah jawaban tiga kali lipat — 1.681 ha versus 560 ha — pada data yang sama persis. Tidak ada yang keliru, tidak ada bug. Yang berubah cuma satu keputusan yang biasanya tidak pernah disebutkan dalam laporan.

Kalau angka Anda meleset agak jauh dari tabel ini, penyebabnya kemungkinan besar arsip yang bertambah — citra 2026 masih terus masuk — bukan kesalahan pengetikan.

7 · Ekspor dan grafik 10 menit

Peta di layar bagus untuk diskusi, tapi cepat atau lambat hasilnya perlu masuk QGIS, ArcGIS, atau lampiran laporan. Untuk itu ada Export.

Export.image.toDrive({
  image:       hilang.selfMask().toByte(),
  description: 'kehilangan_vegetasi_konawe',
  folder:      'GEE_workshop',
  region:      area,
  scale:       20,
  maxPixels:   1e10
});

Jalankan skripnya. Perhatikan: tidak ada yang terjadi — belum. Buka tab Tasks di panel kanan, dan Anda akan melihat satu tugas menunggu dengan tombol RUN di sebelahnya. Klik tombol itu, dan ekspor baru benar-benar berjalan.

Ini sering membingungkan pemula. Export di dalam skrip hanya mendaftarkan tugas; Andalah yang harus menjalankannya. Hasilnya masuk ke Google Drive, di folder yang disebutkan, sebagai GeoTIFF bergeoreferensi yang siap dibuka di QGIS.

Untuk area seukuran latihan ini, prosesnya beberapa menit. Untuk satu provinsi, bisa berjam-jam — dan itu wajar; ekspor berjalan di latar belakang, Anda boleh menutup perambannya.

Grafik deret waktu

Satu hal lagi yang cepat dan berkesan: melihat kehijauan berubah sepanjang waktu.

var deret = ee.ImageCollection('COPERNICUS/S2_SR_HARMONIZED')
  .filterBounds(area)
  .filterDate('2019-01-01', '2026-06-30')
  .filter(ee.Filter.lte('CLOUDY_PIXEL_PERCENTAGE', 40))
  .map(maskAwan)
  .map(function(citra) {
    return citra.normalizedDifference(['B8', 'B4']).rename('NDVI')
                .copyProperties(citra, ['system:time_start']);
  });

var grafik = ui.Chart.image.series({
  imageCollection: deret,
  region:  area,
  reducer: ee.Reducer.mean(),
  scale:   100
}).setOptions({
  title:  'Rata-rata NDVI, 2019-2026',
  vAxis:  {title: 'NDVI'},
  hAxis:  {title: 'Tanggal'},
  lineWidth: 1,
  pointSize: 3
});

print(grafik);

Grafiknya muncul di Console. Garisnya bergerigi — itu sisa pengaruh awan dan perbedaan sudut matahari — tapi kecenderungan jangka panjangnya terbaca jelas.

Perhatikan copyProperties(citra, ['system:time_start']). Tanpa itu, citra hasil perhitungan kehilangan stempel waktunya dan grafik tidak tahu harus meletakkannya di mana pada sumbu tanggal. Ini kesalahan klasik yang menghabiskan banyak waktu orang.

Skrip lengkap

Seluruh workshop dalam satu potong. Bagikan ini di awal kelas supaya peserta yang tertinggal bisa menyusul.

// =====================================================================
//  Workshop GEE JavaScript - deteksi kehilangan vegetasi
//  Mandiodo, Konawe Utara, Sulawesi Tenggara
// =====================================================================

// --- 1. Wilayah kajian ------------------------------------------------
var titik = ee.Geometry.Point([122.25, -3.333]);   // [BUJUR, LINTANG]
var area  = titik.buffer(6000);                    // radius 6 km, meter
Map.centerObject(area, 12);

// --- 2. Buang piksel awan --------------------------------------------
function maskAwan(citra) {
  var scl = citra.select('SCL');
  var bersih = scl.neq(3)      // bayangan awan
    .and(scl.neq(8))           // awan sedang
    .and(scl.neq(9))           // awan tinggi
    .and(scl.neq(10))          // cirrus
    .and(scl.neq(11));         // salju/es
  return citra.updateMask(bersih);
}

// --- 3. Komposit median per periode ----------------------------------
function komposit(mulai, selesai) {
  return ee.ImageCollection('COPERNICUS/S2_SR_HARMONIZED')
    .filterBounds(area)
    .filterDate(mulai, selesai)
    .filter(ee.Filter.lte('CLOUDY_PIXEL_PERCENTAGE', 60))
    .map(maskAwan)
    .median();
}

var sebelum = komposit('2023-01-01', '2023-12-31');
var sesudah = komposit('2026-01-01', '2026-06-30');

Map.addLayer(sebelum.clip(area), {bands:['B4','B3','B2'], min:0, max:3000}, 'Sebelum 2023');
Map.addLayer(sesudah.clip(area), {bands:['B4','B3','B2'], min:0, max:3000}, 'Sesudah 2026');

// --- 4. NDVI dan selisihnya ------------------------------------------
var ndviSebelum = sebelum.normalizedDifference(['B8','B4']).rename('NDVI');
var ndviSesudah = sesudah.normalizedDifference(['B8','B4']).rename('NDVI');
var selisih     = ndviSesudah.subtract(ndviSebelum);

Map.addLayer(selisih.clip(area),
  {min:-0.4, max:0.4, palette:['red','white','green']}, 'Selisih NDVI');

// --- 5. Ambang batas dan luas ----------------------------------------
var AMBANG = -0.15;                 // pilihan, bukan kebenaran - sebutkan saat melapor
var hilang = selisih.lt(AMBANG);

Map.addLayer(hilang.selfMask().clip(area), {palette:['red']}, 'Kehilangan vegetasi');

var luas = hilang.multiply(ee.Image.pixelArea()).divide(10000)
  .reduceRegion({
    reducer:   ee.Reducer.sum(),
    geometry:  area,
    scale:     20,
    maxPixels: 1e10
  });
print('Luas kehilangan vegetasi (ha):', luas);

// --- 6. Ekspor --------------------------------------------------------
Export.image.toDrive({
  image:       hilang.selfMask().toByte(),
  description: 'kehilangan_vegetasi_konawe',
  folder:      'GEE_workshop',
  region:      area,
  scale:       20,
  maxPixels:   1e10
});

// --- 7. Grafik deret waktu -------------------------------------------
var deret = ee.ImageCollection('COPERNICUS/S2_SR_HARMONIZED')
  .filterBounds(area)
  .filterDate('2019-01-01', '2026-06-30')
  .filter(ee.Filter.lte('CLOUDY_PIXEL_PERCENTAGE', 40))
  .map(maskAwan)
  .map(function(citra) {
    return citra.normalizedDifference(['B8','B4']).rename('NDVI')
                .copyProperties(citra, ['system:time_start']);
  });

print(ui.Chart.image.series({
  imageCollection: deret,
  region:  area,
  reducer: ee.Reducer.mean(),
  scale:   100
}).setOptions({title:'Rata-rata NDVI, 2019-2026', vAxis:{title:'NDVI'}}));

Setelah workshop

Skrip yang kita bangun tadi berjalan untuk satu wilayah dan satu pasang periode. Selama kebutuhannya sebatas itu, Code Editor sudah lebih dari cukup, dan banyak penelitian selesai tanpa pernah beranjak dari sana.

Persoalan muncul ketika pertanyaannya berubah menjadi: bagaimana kalau untuk lima provinsi sekaligus? Dua puluh empat tahun? Dengan pemisahan lahan gambut? Sambil mencatat sumber data tiap angkanya supaya bisa dikutip? Menyalin-tempel skrip untuk tiap wilayah adalah cara tercepat menghasilkan hasil yang tidak bisa direproduksi.

Di titik itulah pendekatan berbasis skrip Python jadi masuk akal — dan itulah yang dikerjakan earthchange, paket yang menjadi isi utama repositori ini. Seluruh logika yang kita tulis hari ini (saring, mask awan, komposit, NDVI, selisih, ambang, luas, ekspor) menjadi satu baris:

earthchange -s deforestation --lat -3.333 --lon 122.25 --radius 6

Konsepnya persis sama. Yang bertambah: tujuh belas skenario siap pakai, statistik yang otomatis mencatat sumber datanya, dan kemampuan menjalankan banyak wilayah dalam satu perintah.

Urutan belajar yang saya sarankan Mulai dari Code Editor sampai Anda benar-benar paham apa yang terjadi di tiap langkah — persis seperti hari ini. Baru pindah ke Python ketika pengulangan mulai terasa menjengkelkan. Melompat ke Python sebelum paham konsepnya hanya memindahkan kebingungan ke tempat yang lebih sulit di-debug.

Bacaan lanjut

  • Panduan resmi Earth Engine — rujukan utama, lengkap dengan contoh yang bisa langsung dijalankan.
  • Katalog dataset — cari dataset, lihat nama band dan rentang tanggalnya. Kunjungi ini sebelum menulis kode apa pun.
  • Cloud-Based Remote Sensing with Google Earth Engine — buku gratis, sangat baik untuk pendalaman setelah workshop.
  • Tutorial earthchange — langkah berikutnya, versi Python.
